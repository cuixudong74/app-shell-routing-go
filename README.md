# app-shell-routing-go

服务端渲染的应用外壳与嵌套路由能力。页面由多层级路由与布局组合而成，
每个路由可声明数据加载逻辑，慢数据通过流式事件补齐，导航支持取消。
整条链路只在本进程内完成，通过本地回环 HTTP 即可复现全部行为。

## 路由语义（router 包）

- 路径模式由段组成：`users` 为静态段，`:id` 为参数段，`*rest` 为通配段。
  通配段只能出现在模式末尾；参数名与通配名不能为空。
- 匹配优先级确定且可复现：**静态段 > 参数段 > 通配段**，逐段比较；
  完全相同的段按字面量字典序、再按段数决胜。装配时按此排序，
  与声明顺序无关。
- 冲突检测在装配阶段（`router.Build`）整体拒绝：
  - 路由 ID 重复；
  - 同层模式不可区分（如 `:id` 与 `:name`、两条相同静态路径、两条通配），
    因为匹配结果将依赖声明顺序；
  - 非法模式（空参数名、通配段不在末尾等）。
  冲突错误为 `*router.ConflictError`，携带双方路由 ID 与模式。
- 匹配沿树自顶向下进行，子树失败时按固定顺序回退到下一个候选，
  结果确定。未命中返回 `ok=false`，由上层进入明确兜底
  （`nav` 层输出 `error` + `done` 事件），不会静默失败。

## 数据加载契约（loader 包）

- 加载器签名：`func(ctx, LoadContext) (any, error)`，按 `LoaderID` 注册。
- `LoadContext` 提供：本段及上层合并后的 `Params`、按路由 ID 索引的
  上层已就绪数据 `Parents`、当前 `RouteID`。
- **顺序保证**：沿匹配链上层数据必先于下层就绪（`LoadChain`、渲染器均如此）；
  同层之间通过 `LoadSiblings` 并发加载，结果顺序与输入一致。
- 失败时返回 `*loader.LoadError`，定位到具体路由并携带原因（`Unwrap` 可得）。
- 加载器返回 `nil` 数据被视为错误：缺失数据不得当成空值继续渲染。

## 流式输出（render 包）

事件序列（NDJSON，每事件一次写入，顺序稳定）：

1. `shell`：应用外壳，含每级路由的 `<section data-route="...">` 占位，结构完整闭合；
2. `data`：某路由数据就绪并补齐，按链顺序（上层先于下层），每路由恰好一次；
3. `error`：就近错误边界捕获的失败，携带路由 ID 与原因；
4. `done`：恰好一次且在最后——无论成功还是边界捕获错误，客户端总能看到确定终止。

- 慢数据不阻塞外壳：外壳先行，数据随后补齐；尚未就绪的数据绝不标记为完成。
- 上下文取消后立即停止写入，不输出 `done`，不留半写入状态。

## 错误边界

每个路由是其子树的就近错误边界：某级加载失败时，输出该级的 `error`
事件并停止下钻，已就绪的上层结果保持有效，随后以 `done` 收尾——
子路由出错不拖垮整棵树，也不会输出空白页面或半截结构。
未命中路由等未捕获情形由 `nav` 层兜底为明确的 `error` 事件。

## 导航与取消（nav 包）

- `Navigator.Navigate(path)` 返回该代际独占的事件通道与取消函数。
- 新导航到来时取消旧导航，代际号单调递增（`Current()` 可观察）。
- 每次导航独占通道，过期代际的结果永远不会混入较新的代际；
  取消或超时后通道关闭，不再产出任何事件。

## 路由清单（manifest 包）

清单为版本化 JSON，当前版本为 **2**：

```json
{
  "version": 2,
  "routes": [
    {"id": "root", "path": "", "type": "static", "children": [
      {"id": "user", "path": ":id", "type": "param", "loaderId": "userLoader"}
    ]}
  ]
}
```

- `type` 取值为 `static` | `param` | `wildcard`，且必须与路径模式推断一致。
- **版本演进**：版本 1 的清单（字段 `loader`、无 `type`）按声明的迁移规则
  自动升级：`loader` → `loaderId`，`type` 按路径推断。
- 无法识别的版本、未知路由类型、类型与路径不一致、非法路径模式，
  均在 `Parse` 阶段明确拒绝并说明原因，绝不静默跳过或按默认值处理。

## 静态资源清单

`BuildAssets(routes, assets)` 为每个路由产出资源条目：

- 条目按路由 ID 排序、资源按字典序排序，序列化无 map 迭代，
  相同输入下 `Bytes()` 逐字节一致；
- 每个路由独立成条目，局部改动只影响相关路由的条目，其余保持原样；
- 资源指向不存在的路由会被拒绝并定位。

## HTTP 端点（server 包，本地回环）

- `GET /render?path=/users/42`：以 `application/x-ndjson` 流式返回事件序列；
  新请求会取消上一次未完成的导航（单客户端应用外壳语义）。
- `GET /generation`：返回当前导航代际号。
